### Bloque B — Motor de cálculo (completado)

Rewrite completo de `generarLiquidaciones()` en `liquidaciones.html`.

Fórmula implementada:
```
premio_puesto = max(bolsa × dist_premios[pos] / 100 + bonos, ganancia_minima)
share_actor   = premio_puesto × porcentaje_base
descuento     = share_actor × (fondo_solidario_pct + incentivo_pct) / 100
neto          = share_actor - descuento
```

Edge cases cubiertos: empates (promedio), descalificados (excluidos), forfait (excluidos), mismo propietario en múltiples carreras, idempotencia (borra borradores previos, bloquea si hay aprobadas/pagadas).

Resultado del test sintético: **11 liquidaciones generadas**, montos verificados contra cálculo manual. Data de test limpiada.

## Lecciones críticas del día (ver GOTCHAS.md #27/28/29)

1. **Columnas GENERATED no se incluyen en INSERT** — `total_neto` y `monto_neto` son `GENERATED ALWAYS AS`. Postgres las calcula solo; incluirlas en el payload rompe el INSERT.

2. **`.catch(()=>{})` oculta bugs críticos** — El motor de liquidaciones nunca había funcionado por este patrón. Queries fallaban en silencio y el código seguía. Siempre `.catch(err => console.error(...))`.

3. **Mismatch silencioso código/schema** — `resultados.html` escribía `apuestas` y `motivo_descalificacion` mientras la DB tenía `dividendos` y `motivo_desc`. Sin verbose error handling pasó desapercibido por meses.
