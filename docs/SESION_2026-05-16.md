### 1. Banda negra / tabla apretada (max-width 1100 → 1600 px)

La tabla de ratificación se veía comprimida en pantallas anchas porque el contenedor tenía `max-width: 1100px`. Se amplió a `1600px`. Efecto secundario positivo: el botón "⚠ Mal inscripto" dejó de hacer wrap porque la columna Acciones ganó ancho sin necesidad de tocar los estilos de los botones.

- **`programa.html`**: ya ordena por `numero_partidor` y lo renderiza correctamente. Esa página es post-sorteo, donde el número de gatera sí es definitivo.
- **`numero_partidor` en DB**: la columna se conserva intacta. Solo se dejó de renderizar en `ratificacion.html`.

## 🚧 PENDIENTE PARA LEONARDO — Ejecutar en Supabase SQL Editor

Antes de usar el botón **Confirmar carrera** en producción, verificar si la columna `carreras.estado` tiene un CHECK constraint que limite los valores permitidos. Si lo tiene, hay que extenderlo para aceptar `'confirmada'`.

### Paso 1 — Verificar si existe el constraint

```sql
SELECT conname, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid = 'carreras'::regclass AND contype = 'c';
```

Resultado esperado:
- Si no devuelve nada con `estado IN (...)`: no hay constraint, el botón funciona directo, no hay que hacer nada más.
- Si devuelve algo tipo `CHECK (estado IS NULL OR estado IN ('reabierta','anulada'))`: anotar el `conname` (nombre del constraint) y seguir al Paso 2.

### Paso 2 — Si existe constraint, extenderlo

Reemplazar `<NOMBRE_DEL_CONSTRAINT>` por el `conname` del Paso 1:

```sql
ALTER TABLE carreras DROP CONSTRAINT <NOMBRE_DEL_CONSTRAINT>;
ALTER TABLE carreras ADD CONSTRAINT carreras_estado_check
  CHECK (estado IS NULL OR estado IN ('reabierta', 'anulada', 'confirmada'));
```

### Paso 3 — Probar

Volver a la pantalla de ratificación y hacer click en `✅ Confirmar` en cualquier turno. Si no tira error de constraint violation, está OK.

### Síntoma si falta este paso

Al hacer click en `✅ Confirmar`, el frontend va a mostrar un toast tipo:
`Error: new row for relation "carreras" violates check constraint "carreras_estado_check"`

- line-height 1.35 → 1.25

Resultado esperado: las observaciones ocupan la mitad de altura vertical y todo el PDF entra en una sola página A4 horizontal.

Si en el futuro las observaciones son mucho más largas y vuelve a hacer overflow, próximo paso es bajar a 5.5pt o moverlo a `column-count: 3`.

### Fix — Reducir espacio de headers/footers del browser al imprimir

El browser agrega su propio encabezado ("Ratificados y forfait — SGH") y pie (URL de GitHub Pages + número de página) que consumen ~2 renglones cada uno y empujaban contenido a página 2.

Tres cambios:
- `@page` pasa de `margin-top: 5mm; margin-bottom: 6mm; margin-left/right: 8mm` a `margin: 0`. Algunos browsers, al ver margin 0, dejan de reservar el espacio para sus propios headers (no es universal pero ayuda).
- `#print-only` toma el padding interno (4mm vertical, 6mm horizontal) para que el contenido no quede pegado al borde físico del papel.
- Antes de llamar `window.print()`, se guarda el `document.title` original, se reemplaza por un espacio ` ` (los browsers no aceptan vacío total — usan "about:blank"), se imprime, y al evento `afterprint` se restaura el title. Resultado: si el usuario tiene "Encabezados y pies" activado en el diálogo, va a ver solo un espacio en blanco en lugar del nombre largo.

Limitación: el pie con URL + número de página solo se puede eliminar destildando "Encabezados y pies" en el diálogo de imprimir (Chrome: "Más ajustes" → desmarcar "Encabezados y pies"). Esa preferencia queda guardada por el browser.

### Tanda — PDF en A4 vertical con 3 columnas

Cambio de orientación del PDF de ratificación. Antes: landscape con grid 5×N. Ahora: portrait con grid 3×N.

Razón: en vertical hay más alto (297mm) pero menos ancho (210mm). Con 5 columnas los nombres largos de SPCs ("MALENUCHI JACK", "AMIGUITO PELIGROSO") se rompían en 2 líneas y los bloques quedaban muy comprimidos. Con 3 columnas cada bloque tiene ~66mm de ancho, más legible.

Cambios:
- `@page { size: A4 portrait; margin: 0; }`
- `.pi-cols { grid-template-columns: repeat(3, 1fr); }`

Nota: CAMBIO C (COLS_GRID) no se aplicó porque la constante no existía en el código — no hay lógica de span dinámico en esta versión.
