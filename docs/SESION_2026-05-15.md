### Feature 1: Cierre de ratificación por hora

**SQL ejecutado:**
```sql
ALTER TABLE reuniones ADD COLUMN hora_cierre_ratificacion TIME NOT NULL DEFAULT '12:00:00';
```

**Lógica de cierre (hora local del browser):**
- `reunion.fecha > hoy` → ABIERTA
- `reunion.fecha == hoy AND now < hora_cierre` → ABIERTA
- `reunion.fecha == hoy AND now >= hora_cierre` → CERRADA
- `reunion.fecha < hoy` → CERRADA

**UI:** badge `Cierre HH:MM hs — ABIERTA` (verde) / `CERRADA` (rojo) en el selector-bar.

**Cuando CERRADA:** peso input `disabled`, jockey select `disabled`, todos los botones de acción `disabled` con tooltip "Ratificación cerrada".

**Deuda D.x:** no hay UI para editar `hora_cierre_ratificacion` por club — por ahora el valor se cambia desde Supabase. Dejado como D.x deliberado.

### Feature 2: Congelamiento de peso al cierre

Al cargar una reunión CERRADA, la función `congelarPesos()` copia `peso_declarado → peso_final` para todas las inscripciones en estado `ratificado` que tienen `peso_final === null`. Opera en paralelo (`Promise.all`), actualiza los inputs en DOM. Idempotente: si ya tienen `peso_final`, no hace nada.

### Feature 3: Alerta de colisión de jockey

Al renderizar cada sección de carrera, se calcula un `jockeyCount` por `jockey_titular_id`. Filas con el mismo jockey en la misma carrera reciben clase `jockey-duplicado` (fondo naranja sutil) y badge `⚠ dup.` en la celda. La función `recalcJockeyColisiones(carreraId)` recalcula dinámicamente tras cada cambio de jockey vía `onJockeyChange`. No bloquea ninguna acción — solo alerta visual.

## Bloque D Sub-tanda 1 — Programa Hípico

### Estado previo

`programa.html` ya existía en el repo con un layout avanzado: auth, selector de reunión, header del programa (logo, nombre club, fecha, hipódromo), condiciones crudas de carrera, bolsa y distribución de premios, tabla de inscriptos con propietario + entrenador + últimas 5 performances, CSS @media print A4 landscape.

### Ajustes aplicados en D.1

1. **Filtro de inscripciones** (crítico): `.neq('estado','forfait')` → `.eq('estado','ratificado')`. El archivo anterior mostraba inscriptos y mal_inscrito; solo ratificados van al programa.

2. **Columna Caballeriza**: no estaba en la tabla ni en las queries. Agregada a `init()` (query de caballerizas), al global `caballerizas={}`, y como columna en thead/tbody. Colspan: 7 → 8.

3. **Fallback nombre carrera**: `Carrera N` → `Turno N` (consistencia con cambio de Tanda 1 en ratificacion.html).

4. **Botón back**: `reuniones.html` → `index.html` (consistencia con resto del sistema).

### Decisiones de estilo (autonomía)

- **Layout**: Playfair Display (serif) para headers, DM Sans para datos de tabla — mismo sistema que el resto del app.
- **Print**: A4 landscape, márgenes 10mm, fondo blanco, bordes grises, thead gris claro. Sin color en impresión.
- **PDF Palermo**: el PDF de referencia no estaba en el repo. El layout se basó en el patrón ya implementado en `inscripciones.html > printInscriptos()` que sí tiene estilo Palermo. No se inventó desde cero.
- **Columnas extra** conservadas del archivo preexistente: Propietario, Entrenador, Últimas 5 performances. El spec D.1 pedía mínimo # | SPC | Caballeriza | Jockey | Peso; la implementación es un superset.
