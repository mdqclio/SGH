### 2.1 Verificado que el cero es real y no un JOIN que se come filas

El `[]` de arriba sale de una consulta con `JOIN` — si una inscripción tuviera
`spc_id` nulo, desaparecería en silencio. Recontado con `LEFT JOIN`, que no puede
esconder nada:

```sql
SELECT c.numero_turno,
       count(i.id) AS inscripciones,
       count(*) FILTER (WHERE s.sexo IN ('macho','castrado')) AS machos_o_castrados,
       count(*) FILTER (WHERE s.sexo = 'hembra')              AS hembras,
       count(*) FILTER (WHERE i.spc_id IS NULL)               AS sin_spc,
       string_agg(DISTINCT i.estado::text, ', ')              AS estados
FROM reuniones r
JOIN carreras c           ON c.reunion_id = r.id
LEFT JOIN inscripciones i ON i.carrera_id = c.id
LEFT JOIN spcs s          ON s.id = i.spc_id
WHERE r.numero = 9 AND r.club_id = '0649e9c5-9e87-4aad-842f-101458e6b33c'
GROUP BY c.numero_turno ORDER BY c.numero_turno;
```
```

-------+---------------+--------------------+---------+---------+------------
     1 |             2 |                  2 |       0 |       0 | inscripto
     2 |             0 |                  0 |       0 |       1 | null
     3 |             0 |                  0 |       0 |       1 | null
     4 |             0 |                  0 |       0 |       1 | null
     5 |             0 |                  0 |       0 |       1 | null
     6 |             0 |                  0 |       0 |       1 | null
     7 |             0 |                  0 |       0 |       1 | null

    10 |             0 |                  0 |       0 |       1 | null
    11 |             1 |                  0 |       1 |       0 | inscripto
```

El `sin_spc = 1` de los turnos vacíos es el artefacto del `LEFT JOIN` —la fila
sintética de "no hay inscripción"—, no una inscripción rota: `inscripciones = 0`
en la misma línea. Los turnos 1 y 11, que sí tienen gente, marcan `sin_spc = 0`.
